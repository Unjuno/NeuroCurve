# 公開運用と復旧

## 公開前の停止条件

この配布物はローカルで起動可能です。公開環境への配備は今回実行していません。Vercel/Railwayの作成・デプロイ書き込み操作は、このセッションで取得できたアクションにありませんでした。既存のGitHub mainも変更していません。

公開前に、HTTPS・公開ブラウザE2E・実際のプロキシ/CDN・バックアップ復元・運営連絡先と利用条件を確認してください。画面とローカルAPIが動いたことだけを、本番サービス完成の証拠にしないでください。

## 配備方式

この版のサーバーは**永続ディスクを持つ単一Nodeプロセス**です。SQLiteを一時ディスクしか持たないサーバーレス関数へ置かないでください。複数レプリカや別々のローカルDBを使う水平スケールは未対応です。静的ファイルだけを配信する場合、共有APIは使えません。Vercel等のサーバーレス配備を行うなら、まず永続DBと独立失効台帳に対応するアダプタを別途実装・試験する必要があります。

Node.js 24の保守中パッチ版、専用OSユーザー、HTTPSリバースプロキシを想定します。アプリを直接インターネットのHTTPポートへ公開しないでください。Caddy等を同じホストで使う例:

```caddyfile
neurocurve.example {
  reverse_proxy 127.0.0.1:4173 {
    header_up X-Real-IP {remote_host}
  }
  # /f/* と /api/* をキャッシュしない。本文やAuthorizationをログに記録しない。
}
```

`neurocurve.example`は置換すべき例示名です。取得済みドメインではありません。

サーバー起動の設定:

```sh
NODE_ENV=production \
PUBLIC_ORIGIN=https://neurocurve.example \
HOST=127.0.0.1 PORT=4173 \
DATA_PATH=/srv/neurocurve/content/content.sqlite \
LEDGER_PATH=/srv/neurocurve/revocations/ledger.sqlite \
TRUSTED_PROXY_IPS=127.0.0.1,::1,::ffff:127.0.0.1 \
RATE_SALT="$(cat /run/secrets/neurocurve_rate_salt)" \
node server/index.js
```

ソルトは自分で安全に生成した32文字以上の秘密値を秘密管理基盤に登録してください。公開ソースやログへ出さないでください。プロキシIPは実際の接続元と一致させ、公開側からX-Real-IPを偽装できない構成にします。信頼設定がない場合、送信ヘッダーを信用せずTCP接続元で制限します。リバースプロキシ配下では全利用者が同一IPになるため、そのまま本番にしないでください。

## 保存と権限

- content DB: 投稿定義、メタデータ、削除キーのハッシュ、冪等化情報。
- 独立ledger DB: 共有IDのSHA-256と失効時刻だけ。旧URL再利用防止のためサービス存続中保持。
- rateカウンター: HMAC(IP)と件数・期限。期限経過後に削除。
- 通報: 7日を超えたものを整理。個人情報を入力させない。
- ドラフト、学習データ、モデル重み、学習結果: サーバーには保存しない。

ファイルは専用ユーザーだけが読める場所に置いてください。DB本体はアプリが0600で作成し、ディレクトリも新規作成時0700です。既存ボリュームのアクセス権は運営側で確認してください。バックアップには秘密キーの原文は入りませんが、公開URLを含む投稿データがあるため機密扱いにしてください。

## 期限と掃除

取得・共有HTML・OG画像は毎回同じ有効性検査を行います。期限に達したデータは定期掃除を待たず配信しません。失効を観測した時点で台帳へ記録するため、その後にOS時計が巻き戻っても再公開されません。正確なUTC時計の運用は必要です。

起動時と1時間ごとに期限切れ本体を削除します。手動削除は台帳を先に確定してから本体を消します。台帳更新に失敗した場合、処理成功を返しません。台帳書き込み後の本体削除失敗でも配信は止まります。

```sh
node scripts/admin.js cleanup
node scripts/admin.js reports
node scripts/admin.js revoke 0123456789abcdef0123456789abcdef --confirm
```

末尾のIDは例です。管理CLIは同じDATA_PATH・LEDGER_PATH設定を引き継いでください。ファイル権限を持つ運営者だけが実行します。通報の一覧を公開HTTP APIにしないでください。管理用削除は削除キー紛失の本人確認の代替ではありません。

## バックアップ・復元

```sh
node scripts/admin.js backup /srv/neurocurve-backups/content
```

SQLiteのオンラインbackup APIを使用し、同じディレクトリ内の本ツール生成バックアップのうち30日より古いものを削除します。外部のバックアップ製品にも最大30日の保持期限を設定してください。上記コマンドを定期実行しない限り、自動バックアップは作成されません。

**ledgerはcontentの復元ポイントと独立して現在状態を維持・冗長化してください。** 同じ古い時点へ巻き戻す運用は不可です。無期限の手動削除があるため、ledgerを単に30日ごとに全消去してはいけません。

復元手順:
1. アプリを停止し、公開トラフィックを遮断する。
2. 現在の独立ledgerが健全で、今回のcontentと対になるinstanceであることを確認する。
3. content DBだけを復元する。古いcontentのWAL/SHMを混在させない。
4. `node scripts/admin.js cleanup`を実行する。期限と台帳による失効を確認する。
5. 削除済み・期限切れURLについてHTML/API/PNGが404であることを検査してから公開する。

ledgerまで紛失した場合、投稿が復活しないと保証できません。独立した最新台帳を復元できるまで公開を再開しないでください。

## 必須の本番確認

- `/healthz`、トップ、ポリシー、3データセット、Worker起動と停止。
- 投稿に未同意の時はPOSTなし、同じPOSTの再送が同一ID、秘密キーがURL/ログに出ない。
- 期限直前/直後、削除直後、API/HTML/PNG/HEADすべての拒否。
- `Cache-Control: no-store`をCDNが上書きしないこと。失効後のoriginの200再配信がないこと。
- ブラウザの既表示・外部SNSのキャッシュは回収できない旨を告知。
- 代理サーバーからのIPを信頼する範囲と、共有回線での誤制限。
- ログ保持7日以内を運営側で設定。キーと本文のログを無効化。
- 通報を実際に確認できる運営体制、連絡先、投稿条件の専門家確認。
