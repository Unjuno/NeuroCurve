# v0.9.0 — WebGPU選択・実行時検証（実機GPU検証待ち）

## 変更
- WebGPUコンピュート演算の経路を追加。サンプル並列の順伝播/逆伝播、バッチ勾配集約、勾配クリッピング、Adamの更新をGPUシェーダーで実行。
- 未対応端末ではCPU Float64へ自動フォールバック。GPU必須モードはGPUが使えない場合に明示エラー。
- C¹ Hermite Float32 LUTにより、手描き/PCHIP、谷関数、検証済み数式・標準関数をGPUで利用可能にする。511点を超える追加走査を使い近似誤差をチェック。
- 最初のGPU学習バッチでCPUによる損失・勾配参照との実照合。失敗を結果に記録。
- 専用の `/gpu-check.html` を追加。端末のWorkerでGPUを確認する診断。アクセスはユーザー操作で開始。
- 比較表にbackendを追加。学習ログにGPU設定・勾配検証・LUT誤差を記録。
- ホームページは検索可能、共有URLのみnoindexに変更。共有データの一覧は設けない。

## 検証と公開制約
- Nodeの単体・統合テスト、CSP静的検査、オフラインブラウザDOMテストは実施。
- **実機WebGPUシェーダーコンパイルと学習は、この環境のURLブロック制約のため未検証**。GPU利用が確認できるまで本番GPU対応の合格宣言はしない。
- 対応ブラウザがない・GPU失敗の場合はCPUに戻る。WebGLバックエンドは実装していない。ソフトウェアのWebGPUアダプターは可能な範囲で除外する。
- サーバーの本番公開、独立失効台帳のバックアップ、公開URL E2Eも未検証。

# v0.8.0 — ローカル実装候補版

## 同梱物
手描き/PCHIP、数式の安全な構文解析、1〜16谷の調整、数理解析、CPU学習、実測比較、手動エクスポート、匿名の期限付き共有API、削除・通報・管理CLI、テスト・実行証拠。

## 仕様から具体化した判断
- 初期バックエンドはnative JavaScript Float64 CPU。GPUとTensorFlow.jsは使用しない。
- 固定モデルは32→32、バッチ64。プロトコルを全比較で一致させる。
- 本番サーバーは永続ディスクの単一Nodeプロセス。SQLiteを一時ディスクのサーバーレスへ配備しない。
- 復元に備え、削除台帳は内容のバックアップと独立して保持。投稿内容を含まないIDハッシュはサービス存続中保持する。元仕様の曖昧な「必要期間後に台帳消去」は、古いIDの再使用・復活防止のため、この運用定義に具体化する。
- 不存在・失効・取消済みは一律404。OG画像も都度有効性検査。
- 関数の範囲外は端点の接線外挿。谷の深さと実際の局所最小数を混同しない。
- 検証結果は一般的優位性の保証にせずUNCERTAINを維持する。
