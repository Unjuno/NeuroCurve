# NeuroCurve — Webサイト統合仕様 v0.8

**更新日：2026-10-26**  
**状態：実装前の修正版仕様案。リポジトリ変更なし。**  
**対象：`Unjuno/NeuroCurve`／Public／Apache-2.0**

## 1. 製品の目的と確定条件

NeuroCurveは、手描き・数式・パラメータからニューラルネットワークの活性化関数を設計し、数学的性質を解析し、必要に応じてユーザー自身の端末で学習ベンチマークを実行するWebサイトである。学習モデルの評価だけを目的としない。

- **完全公開・ログイン不要**。サイト内の個人アカウント／個人ライブラリ／下書きの自動保存を提供しない。
- 作業中の曲線と学習結果はブラウザの一時メモリに保持。**明示的なファイル書き出し**は許可するが、ブラウザ内の永続保存は自動実行しない。
- 解析と学習は原則ユーザー端末のCPU・対応GPU上で実行。学習データや結果をサーバーへ自動送信しない。
- 初期の学習データは共通データセットのみ。任意データアップロードと任意コード実行は実装しない。
- **投稿は完全なオプトイン**。投稿した関数定義のみ公開用データベースへ保存する。
- 投稿は**URLを知る人に公開（unlisted）**。公開ギャラリー、公開検索、ランキング、ユーザー一覧は設けない。
- 共有期限は **7日、30日、365日、無期限**から投稿時に選択。初期値は7日。
- 他人はURLから関数を閲覧し、端末内に読み込んで編集・解析・再評価できる。元投稿は不変。

## 2. 画面・操作フロー

### 2.1 Studio

マウス・タッチ・ペンによる手描き、制御点の移動、Undo/Redo、数値での制御点編集を提供。数式入力と「ロジスティック＋複数の谷」のテンプレートも扱う。谷の位置・深さ・幅・間隔・非対称性・成長率・入れ子振動を調整可能にする。

- 描いた直後に曲線・導関数・局所極小／極大・飽和・数値異常を**ローカルで診断**。
- 同じ入力位置に異なる出力値を持つ点列は、黙って近似せず修正を要求する。
- 形状保存型の3次補間（PCHIP）と、構造化した数式モデルの2方式を扱う。
- 元曲線と実際に評価に使う近似曲線を重ねて表示し、近似誤差と谷の消失を可視化する。
- 入力範囲外は、原則として端点の接線による線形延長とする。端点傾きが安全上限を超える場合は自動変更せず、警告して学習実行を禁止する。

### 2.2 Analysis

関数値・1階導関数・可能なら2階微分、停留点、谷の位置／深さ／幅、傾きの符号反転、勾配の極値、飽和傾向、計算時間、実装誤差を表示。**数学的解析結果は学習精度の予測値として扱わない**。

### 2.3 Learning Lab（利用者が明示開始）

- ユーザー端末のブラウザで学習。TensorFlow.js等の実装を候補とし、バックエンド名・バージョン・計算精度・勾配演算対応を**事前自己検査**する。
- GPU非対応、必要演算の勾配未実装、メモリ不足の場合は、対応するCPU経路へフォールバックするか、理由を明記して実行不可とする。
- 学習処理をUIとは分離し、停止・キャンセル・リソース解放・再実行を提供する。
- 共通データ：Two Moons、8×8 Digits、多周波回帰。各データの生成条件・前処理・分割・ハッシュ・バージョンを固定する。
- 初期設定：高速試験1シード・150更新、本評価5シード・600更新。ネットワーク、損失、最適化器、初期重み、バッチ順、データ分割は比較関数間で一致させる。
- 比較対象：ReLU、Swish/SiLU、GELU。分類正解率、回帰RMSE、学習時間、勾配分布、失敗数、谷への入力到達率を個別表示する。
- **異なる端末の処理時間を同一ランキングで比較しない**。研究上の優位性は、1課題・少数シードのみでは宣言しない。

### 2.4 Export

ユーザーが操作した場合のみ、関数定義JSON、CSV、SVG／PNG、PyTorchコード、実験条件・結果をファイル出力できる。これは**ユーザーの手動エクスポート**であり、サイト内の個人保存ではない。

## 3. 投稿仕様：同意と秘密キー

1. ユーザーが「共有する」を選択するまでは、曲線定義を投稿APIへ送信しない。
2. 共有前に、投稿名・説明文（任意）、関数定義、期限、再利用条件、共有先でコピーされ得ることを明示する。同意チェックは初期状態OFFとする。
3. **投稿前にブラウザの暗号学的乱数**で共有ID（128ビット以上）、削除用秘密キー（256ビット）、重複投稿防止ID（128ビット以上）を生成する。秘密キーは投稿前・投稿成功後に提示し、コピーや保存を促す。
4. サーバーには削除キーそのものを送らず、ハッシュ（SHA-256）を送る。サーバーは投稿データを検証し、原子的に保存する。同じ重複投稿防止IDと同一内容の再送は同一共有IDを返す。異なる内容なら競合エラーにする。
5. 共有ページは**保存成功を確認した後のみ**公開可能と表示する。レスポンス消失時は同じIDで再送・照会できるようにする。ページを閉じると未保存情報は失われる旨を事前警告する。
6. 投稿は編集不可。変更したい場合はコピーして新規投稿する。公開期限の延長も不可。

投稿対象：`share_id`、`schema_version`、`engine_version`、関数の点列または検証済み構文木とパラメータ、補間／外挿仕様、任意の表示名・説明、`created_at`、`expires_at`、`delete_token_hash`、定義内容のハッシュ、投稿時の同意規約バージョン。学習結果・GPU情報・メールアドレスは含めない。

初期のサーバー側上限案：投稿JSON 64 KiB、点列512点、構文木64ノード、表示名80文字、説明500文字。数値は有限であることを必須とし、NaN／無限大／不正値は拒否。任意のJavaScript／Python／HTMLは受け付けない。

## 4. 期限・削除・復元

| 事項 | 固定仕様 |
|---|---|
| 期限の選択 | 7日、30日、365日、無期限。初期値7日 |
| 起点 | サーバーが投稿を正常保存したUTC日時 |
| 表示 | UTCの絶対期限を保持し、画面では利用者のタイムゾーンで絶対日時も併記 |
| 判定 | 期限到達の瞬間から、すべての配信経路でアクセス不可（バッチ削除を待たない） |
| 無期限 | `expires_at=null`。サービス継続を永遠に保証する意味ではない |
| 投稿者による取り消し | 秘密キーの照合に成功した場合のみ即時閲覧停止 |
| 本体データ削除 | 期限到達または取り消し後、24時間以内を目標にDB・自サイト画像を消去 |
| バックアップ | 保持は最大30日。復元後の公開前に期限・削除記録を照合して再公開を防止 |
| 外部サービスの複製 | 回収不能な場合があるため、投稿確認時に明示 |

共有ページ、関数取得API、OG画像の**すべて**で同一の有効性チェックを通す。期限切れ・取り消し・不存在は、情報の存在を漏らしにくくするため原則一律 `404` とする（画面では「存在しないか公開終了」と表示）。有効なページや画像でも `Cache-Control: no-store` を付け、CDNの公開キャッシュを無効化する。ブラウザの既表示内容、第三者のスクリーンショット、外部SNSが保存したプレビューは削除保証の対象外。

削除用秘密キーは**共有URL／URLクエリ／ブラウザ履歴／Refererに含めない**。削除時のみHTTPSの`Authorization`ヘッダーで送り、サーバーで安全な比較を行う。ログにはヘッダーや秘密値を記録しない。削除キーを紛失した場合、無認証での所有者確認・復元はできない。違法・権利侵害等への管理者通報は独立した窓口で受け付ける。

バックアップから削除済みの共有が復活しないよう、削除記録の最小限の台帳をバックアップと独立して保持し、復元前の照合を必須とする。台帳は必要な保持期間後に消去する。

## 5. 共有URL・外部サイト連携

- 共有URL：`/f/{shareId}`。共有ID以外の秘密情報は含めない。
- 公開ギャラリー、一覧API、検索、ランキング、サイトマップへの掲載は行わない。
- 共有ページ／OGレスポンスに`noindex`を付与する。`noindex`は認証や機密保持の代わりにはならない。検索エンジンが規則を確認できるよう、このページだけを`robots.txt`でブロックしない。
- SSR等で`og:title`・`og:description`・`og:image`を提供。OG画像は**有効な投稿だけ**を検証済み数値から生成し、第三者URLやユーザーHTMLを描画しない。
- `Referrer-Policy: no-referrer`を付ける。共有はURLコピーとブラウザのネイティブ共有を基本とし、iframe埋め込みはMVP対象外。
- 他の利用者はローカルコピー・編集・再解析・再評価ができる。**他サイトへのURL共有は許可**。転載・派生物の再配布許諾は投稿規約に分けて明記し、NeuroCurve本体のApache-2.0を自動適用しない。

## 6. APIとセキュリティ

| 操作 | インターフェース | 備考 |
|---|---|---|
| 投稿 | `POST /api/shares` | 明示的同意済みの構造化データのみ。冪等化・サイズ・形式を検証 |
| 関数取得 | `GET /api/shares/{id}` | 有効期限と取消状態をチェック |
| 共有ページ | `GET /f/{id}` | 同じ有効性チェック、OG情報の生成 |
| 共有画像 | `GET /f/{id}/og.png` | 失効後は配信しない |
| 投稿削除 | `DELETE /api/shares/{id}` | 削除キーをヘッダーで提示 |
| 通報 | `POST /api/reports` | ログイン不要、スパム対策つき |

- 投稿APIはHTTPS必須。投稿形式はJSONのみ。投稿名・説明は安全なテキストとして出力エスケープし、CSP等の追加防御を適用。
- 数式はホワイトリスト化した演算子と型検査済みパラメータとして解釈し、`eval`や任意コード実行を禁止。
- IP単位の投稿回数制限（初期案：3回／時）と多層レート制限、異常時のBot判定を用意。共有IPでの誤検知も検証。
- セキュリティ目的のログは最小化し、保持期間は初期案7日。IP等の取扱いはプライバシーポリシーで説明する。
- クライアントの数値解析・学習は実行予算（配列サイズ・更新回数・時間）を制限。リソース不足は中断し、UIと端末を回復可能な状態にする。

## 7. 計算正確性・研究品質

- 手描き点列の数式化で谷の数・位置が変化した場合、誤差を表示して利用者に伝える。黙った平滑化はしない。
- 関数値と導関数の基準実装・有限差分（微分不能点は除外）の突き合わせを必須とする。
- 学習では共通データセットの生成条件、分割、前処理、モデル、初期値、最適化設定を固定する。
- 学習結果にバックエンド、ブラウザ、端末種別、dtype、モデル、バッチ数、更新数、シード、時間を付与する。ただし投稿APIに自動送信しない。
- 解析（学習不要）、高速学習（1シード）、本評価（5シード）の結果を混同しない。
- 判定は`PASS`／`FAIL`／`UNCERTAIN`。少数シードや繰り返し最適化した固定テストセットによる一般的優位性を断言しない。複数比較の影響も注記する。

## 8. MVPの受け入れ試験

| ID | 必須試験 | 合格条件 |
|---|---|---|
| T01 | 未同意での投稿 | 投稿APIへ送信されない |
| T02 | 投稿直後の通信断 | 冪等再試行で同じ共有ID、削除キーによる操作が維持される |
| T03 | 期限境界 | 期限直前のGET成功、期限到達時点以降はページ・API・OGがすべて配信拒否 |
| T04 | 不正削除キー | 削除されない、試行制限が効く |
| T05 | 正しい削除キー | 即時アクセス停止、期限内にDB削除 |
| T06 | バックアップ復元 | 削除済み・期限切れ投稿が再び公開されない |
| T07 | CDN／ブラウザキャッシュ | サーバー管理下の配信経路で失効データを再配信しない |
| T08 | 投稿のXSS・不正数式 | スクリプトを実行せず安全に拒否・表示 |
| T09 | 巨大・連続投稿 | サイズ制限・レート制限が作動 |
| T10 | 描画の再現 | 別端末で同じ関数値／曲線を許容誤差内で復元 |
| T11 | 微分・外挿 | 基準微分と一致し、危険な範囲外挙動は実行停止 |
| T12 | ローカル計算 | 関数の解析と学習をサーバー計算なしで実行、失敗時は安全停止 |
| T13 | ベンチマーク | 3共通課題・標準3関数との条件一致と再現ログの確認 |
| T14 | 共有の非掲載 | 投稿一覧・ギャラリー・検索API・サイトマップが存在しない |

**H**：匿名・期限付き共有とローカル評価が安全かつ再現可能に成立する。  
**T**：上記の境界試験・異常系試験、最低30種類の数式テストケース、最低5シードの学習評価。  
**D**：T01〜T14がすべて合格し、未確認事項を公開前に解消した場合のみリリース可。  
**C**：CDNの設定漏れ、秘密キー紛失、バックアップからの復活、非対応GPU、補間誤差、浮動小数点差。  
**U**：微分誤差の測定値、端末ごとの差、シード間変動、データ分割の不確かさを実測して報告。数値しきい値は実装方式決定後に固定する。

## 9. 責任分離と未決定事項

**サイト側**：関数設計のUI、ローカル解析・ローカル学習、投稿受理・失効・削除・安全な共有ページ表示。  
**ユーザー側**：投稿の明示同意、秘密キーの保管、共有先の選択、端末計算資源の提供。  
**第三者側**：SNSなどが既に収集した公開情報について、NeuroCurveから完全な消去は保証できない。

実装前に専門家確認を要する項目：投稿された説明文・画像・関数定義の利用許諾、通報／法的削除手順、プライバシーポリシー、各端末でのバックエンド互換性、適切なCPU・GPUリソース上限。**仕様上の決定であって、検証結果ではない。**

関連分野：Webセキュリティ／分散システム（失効と復元）、数値解析（補間・微分）、機械学習・統計学（比較と不確かさ）、著作権・個人情報保護（公開許諾とログ）。
